# extend-after-export-default-narrow

The control for `extend-after-export-default`: the same source shape (`@Entry @Component`
struct, `export default`, then an `@Extend`) with a single construction in `build()`.

Five bytes of widening sit ahead of `export default ExtendAfterExportNarrow;` and the `@Extend`
is forty bytes behind it, so the helper lands after the export with or without the offset
translation `ets_component::read_component_file` applies. It is here to prove the fix moves
*only* the case where the widening outgrows the gap: with this fixture the pre-fix and post-fix
output are byte-identical.

`golden.ts` / `golden/Index.ts` (generated by `scripts/oracle/run-hvigor.sh`): the export on
line 42, `function __Text__tailPad` on line 43.
