# extend-after-export-default

`@Extend` helpers are emitted where their declaration stood. `export default` is written
*before* the `@Extend` here, so the generated `function __Text__tailPad` has to come after
`export default ExtendAfterExport;` — and the eleven child blocks in `build()` (fifty-five bytes
of widening) must not move it.

This is the regression fixture for the coordinate mix the lowering had: a helper's piece was
placed by an offset measured on the **source**, the statements it is merged with by offsets
measured on the **widened** text the parser reads (the child-block rewrite inserts `() =>` /
`, () =>` and `)` before each construction). With a 34-byte gap between the two declarations,
the 55 bytes of widening ahead of both used to make the helper sort first — the same shape as
clashbox `entry/components/More/Connect.ts`, `More/Request.ts` and
`Settings/Appearance.ts`, where the helper is declared at the very end of the file.

`golden.ts` / `golden/Index.ts` (generated by `scripts/oracle/run-hvigor.sh`) hold the
reference output: `export default ExtendAfterExport;` on line 82, `function __Text__tailPad`
on line 83. Drop the translation in `ets_component::read_component_file` and the three-line
helper comes out ahead of the export, which this comparison reports as a divergence at the
export.

The sibling `extend-after-export-default-narrow` is the control: one construction, five bytes of
widening, far under the gap — the order is right there either way, so the pair separates "the
rule is source order" from "the widening moved the offset".
